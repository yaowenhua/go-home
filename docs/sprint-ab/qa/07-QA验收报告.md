## A2 page_view 埋点 —— ⚠️ PASS（带小缺陷）

### 实测结果
| DoD | 结果 |
|-----|------|
| **DD-A2.1** 登录 POST page-view → 落行；每用户每页面 5min 去重 | ✅ 同 path 重复 4 次仅 1 行；不同 path 分别计数；≥5min 外重新记录（频控正常过期） |
| **DD-A2.2** 匿名不收；无 user_id=null 的 page_view | ✅ 无 token → 401；`user_id IS NULL 的 page_view` = **0** |
| **DD-A2.3** 只浏览不写的用户计入 DAU | ✅ 代码：DAU=`COUNT(DISTINCT user_id) FROM activity_log`（含全部事件类型）；实测 `qgU4…` 用户 pv=2 writes=0，被 DISTINCT user_id 计入 |
| **DD-A2.4** 上报失败零影响 | ✅ 前端 `.catch(()=>{})` + 异步按 `to.fullPath`，后端 30s 批量异步，主流程零阻塞 |
| **DD-A2.5** DAU 卡片反映浏览活跃 | ✅ page_view breakdown 随浏览上升（6→8）；统计接口无 event_type 过滤 |

### 前端埋点（代码审查）✅
`router/index.js` `afterEach`：`if (!authStore.isLoggedIn) return`（匿名不发）→ `activityApi.reportPageView(to.fullPath).catch(()=>{})`。`api/activity.js` POST `/activity/page-view`。`vite build` 通过。

### ⚠️ 缺陷（低风险，非阻塞，建议修）
**无效请求（400）仍落一条 page_view 行**，污染「真实活动日志」与 page_view 统计：
- 根因：`activityLogger` 中间件在 **res.end 钩子** 落库（含频控 key 判定），早于 handler 的 path 校验。当请求体非法（缺 path / path 非字符串）时，handler 正确返回 400，但中间件已把该请求记成一条 `page_view`。
- 实测：`POST /page-view` body `{path:123}` → HTTP 400，但 activity_log 落行 id=61 `path='123.0'`、`statusCode:400`；body `{}` → 400 且落行（fallback originalUrl）。
- 影响：该行会出现在 B1 用户活动列表（显示为「浏览页面 /api/activity/page-view」）并计入 page_view 计数，造成轻度虚增。
- 现实影响低：仅登录用户、真实前端恒传合法 string path 不会触发；属数据卫生/正确性缺陷。
- **建议**：page_view 在 handler 校验通过后再落库（或在 handler 里 `syncRecordEvent` 而非依赖 res.end 钩子对无效请求也记）。不阻塞发布。
